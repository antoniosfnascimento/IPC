# Análise Hierárquica de Tarefas (HTA) - MVP CityFlow

Este documento aplica a metodologia de *Hierarchical Task Analysis* (HTA) à principal jornada de valor do CityFlow. O objetivo desta decomposição é identificar cada ponto de fricção onde o Frontend ou o Backend podem falhar perante o utilizador, estipulando os respetivos tratamentos de erro (Error Handling).

## Tarefa Principal (Macro-Task): Nível 0
**0. Planear Rota Inclusiva Segura** (Objetivo: Ir de "A" para "B" sem cruzar barreiras físicas intoleráveis).

| Hierarquia (HTA) | Título da Sub-Tarefa | Ação do Utilizador (Frontend) | Processo do Sistema (Backend/App) | Condição de Erro & Tratamento |
| :---: | :--- | :--- | :--- | :--- |
| **1.** | **Definir Perfil Base** | Clica num *Card* ou Toggler de "Cadeira de Rodas / Visual / Idoso". | Carrega as constantes (Constraints) matemáticas para o *state* global da App (ex: `max_incline: 0.08`). | **Erro (1.1):** Utilizador não escolhe perfil nenhum.<br>**Tratamento:** O botão de Submeter fica *Disabled* e surge um alerta visual exigindo a seleção de um Perfil. |
| **2.** | **Inserir Coordenadas Iniciais** | Escreve na caixa de texto "Origem" ou clica no botão GPS "A minha localização". | O sistema adquire e sanitiza a String introduzida usando um provider de Geocoding (ex: Nominatim) ou a API `navigator.geolocation` nativa. Pydantic converte para array Float `[Lat, Lon]`. | **Erro (2.1):** Permissões de GPS negadas pelo browser do utilizador.<br>**Tratamento:** Fallback para inserção de texto manual com mensagem amigável: "Por favor insira a origem por texto". A App não pode crashar. |
| **3.** | **Inserir Destino** | Escreve na caixa de "Destino" ou toca com o dedo `onClick` algures no mapa Leaflet. | Transforma a string de texto na coordenada geográfica fina correspondente. | **Erro (3.1):** O destino inserido (ex: "Porto") localiza-se fora da malha pré-carregada na RAM do servidor para Vila Real (Raio > 1.5Km).<br>**Tratamento:** O FastAPI aborta com Erro 400. O Front exibe: "Destino fora da área metropolitana mapeada neste momento." |
| **4.** | **Submeter Rotas (Início API Request)** | Aciona o Botão "Calcular" (Touch Target 44x44px - WCAG 2.5.5). | O Frontend envia o POST Model preenchido para o Backend através do protocolo HTTP. | **Erro (4.1):** Falha de Internet no telemóvel do lado do cliente.<br>**Tratamento:** Toast Notification "Perca de Ligação de Rede", parando o Spinner de Carregamento. |
| **5.** | **Calcular Variáveis de Grafo** | Em modo de espera analítico (Apenas Visão do Spinners no ecrã). | O Motor Python de Rotas executa sobre o `NetworkX` multiplicando todas as 30 mil arestas de Vila Real pelos Pesos e Heurísticas estipuladas. | **Erro (5.1):** As etiquetas OSM das estradas procuradas estão corrompidas e quebram a matemática.<br>**Tratamento:** O `_parse_float()` atua forçando Defaults Mínimos Seguros. Erro silenciado para o utilizador. |
| **6.** | **Validar Barreiras (Extremo)** | (Componente transparente/Imediato durante o passo 5). | O motor Dijkstra tenta ligar a Origem (Nó U) à Chegada (Nó V) através de caminhos com peso finito. O nó de chegada é fisicamente "rodeado de escadas". | **Erro (6.1):** "Caminho Morto" isolado no Grafo (sem soluções abaixo do teto limite).<br>**Tratamento:** FastAPI regressa 424 Failed Dependency. Cliente lê a mensagem e notifica com tolerância: "Destino fisicamente impossível ou isolado pelas regras deste Perfil de Saúde". |
| **7.** | **Renderização Sensorial Sucesso** | Inícia a observação da Rota gerada. | O Leaflet desenha a rota grossa e em linha cheia GeoJSON gerada. A App lança o TTS avisando verbalmente a Início da Viagem. | **Erro (7.1):** A rota está sobreposta a ruas não pedonais que confundem o Leaflet base.<br>**Tratamento:** Camadas Leaflet indexadas corretamente (z-index) garantindo que a Polyline gerada surge sempre por cima e opaca. |

*Nota Metodológica:* Se o passo 6 não falhar (Erro 6.1 gerido ou não despoletado), a macro-tarefa 0 é dada como concluída com sucesso (O utilizador está pronto a iniciar o movimento físico na vida real).
