# Casos de Uso (Use Cases) - MVP CityFlow

Esta secção detalha as interações principais transformando os Requisitos Funcionais em sequências lógicas de ações entre o Sistema e os Atores (Utilizadores com ou sem limitações).

| ID | Nome do Caso de Uso | Ator Principal | Fluxo Principal (Passo-a-Passo) | Resultado Esperado |
| :---: | :--- | :--- | :--- | :--- |
| **UC01** | **Calcular Rota Inclusiva** | Utilizador (João - Cadeira de Rodas) | 1. O ator abre a aplicação CityFlow.<br>2. O ator introduz a "Origem" e o "Destino".<br>3. O sistema deteta o perfil base ativo ('Cadeira de Rodas') e aplica os pesos matemáticos.<br>4. O motor recalcula o menor custo passando o filtro de inclinação (<8%) e evitando escadas.<br>5. O sistema renderiza a *Polyline* no ecrã e avisa de qual a distância final. | O utilizador vê uma rota visual no mapa, totalmente desprovida de escadas e ruas íngremes, pronta a seguir. |
| **UC02** | **Salvar e Alterar Perfil** | Utilizador (Qualquer) | 1. O ator clica no Botão de Perfil do ecrã principal.<br>2. O ator altera os parâmetros (ex: "Largura Mínima: 1m", "Modo: Idoso").<br>3. O ator clica em *Guardar*.<br>4. O Frontend guarda o novo `state` e a aplicação inteira adota as novas regras para a próxima pesquisa. | O perfil fica ativo e visível num autocolante verde no canto do mapa indicando "Perfil de Idoso Ativo". |
| **UC03** | **Ativar Modo Alto Contraste** | Utilizador (Ricardo - Daltónico) | 1. Na UI, o utilizador clica no ícone universal de contraste (meia-lua).<br>2. O Frontend atualiza as tags CSS globais (`dark_matter`).<br>3. O mapa altera os base-tiles de cores diurnas normais para tons cinzentos base e substitui a Rota Azul por Rota Amarela brilhante.<br>4. Textos ganham fonte audaz e contraste de 7:1 (AA/AAA). | Uma interface perfeitamente visível para daltónicos e de baixíssima carga visual. |
| **UC04** | **Reportar Obstáculo em Tempo Real** | Utilizador em movimento (Maria - Baixa Visão) | 1. O ator entra em modo *Easy Read*.<br>2. Depara-se com uma calçada cortada para obras subterrâneas (sem aviso no Google Maps).<br>3. O ator carrega durante 1 segundo no botão massivo "Reportar Caminho Cortado".<br>4. O Frontend usa o GPS atual e diz à API que naquele raio o `is_blocked = True`.<br>5. O sistema limpa a rota atual e força o cálculo imediatamente na direção oposta disponível. | O GPS recalcula a nova alternativa mais segura, tirando a Maria da estrada perigosa para carros e levando ao passeio do lado oposto. |
| **UC05** | **Ler Instruções de Navegação** | Sistema (via API de Voz Nativa Web) | 1. O ator está a meio de um "UC01" seguindo as Linestrings.<br>2. O telemóvel atinge os últimos 15 metros antes da curva de 90 graus à direita.<br>3. O Frontend deteta a métrica espacial, despoleta o TTS da *Web Speech API*.<br>4. Uma voz natural diz: "Atenção, vire à direita na esquina da praça". | O utilizador não precisa de estar a olhar para o telemóvel continuamente, prevenindo desequilíbrios na marcha mecânica. |
| **UC06** | **Tratamento de Caminho Impossível** | Utilizador e Motor Dijkstra | 1. O ator pede rota para um mosteiro antigo onde só existem escadas muito compridas.<br>2. O backend com o Perfil de "Cadeira de Rodas" avalia os nós, multiplicando por x10000.<br>3. Todo o grafo a 1.5Km fecha (nó de chegada isolado).<br>4. Em vez de crashar, a API comunica Status 424. | O Frontend diz carinhosamente "Desculpe, com as limitações atuais, não existe rota minimamente segura para aquele destino. Tente relocalizar-se." |
